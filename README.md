# Quota Guard

Подписочные квоты LLM-провайдеров в OpenCode: панель в Desktop, предупреждения в сессиях и ручное управление — **без автоматических действий**.

Quota Guard читает квоты подписок **ChatGPT, Kimi Ultra и Kimi Ultra Aprobo**, показывает проценты использования, время сброса, кредиты плана ChatGPT и скорость работы LLM в токенах/с, предупреждает при 80% / 95% и даёт переключатели мониторинга и ручную смену модели сессии. Обе Kimi-подписки имеют независимые учётные данные и карточки без суммирования. Плагин **никогда** сам не останавливает сессию и не меняет модель: `automaticActions.interrupt = false`, `automaticActions.switchModel = false` всегда.

- Версия: 0.14.0
- Лицензия: MIT
- Хост: OpenCode V2 (server plugin + Desktop GUI + RPC)
- Связанный сторонний плагин: `opencode-usage-monitor` (TUI-сайдбар) — не изменяется и не требуется для работы Quota Guard.

## Безопасность (инварианты)

1. Только предупреждения. Никаких вызовов `session.interrupt` / автоматического `switchModel`.
2. Смена модели — только явным нажатием пользователя в панели или явным RPC-вызовом `switchModel`.
3. Учётные данные не логируются и не возвращаются в RPC-ответах; статусы содержат только коды ошибок.
4. Кредиты плана показываются как баланс и приблизительные диапазоны сообщений — это данные подписки, а не платёжные реквизиты; в репозиторий не попадают.
5. Выключенный мониторинг: нет запросов к провайдерам, нет предупреждений, таймер остановлен; панель показывает последний снимок.
6. Метрики скорости read-only: используются только события и сохранённые сообщения OpenCode, без вызовов моделей; тексты диалогов в RPC не попадают.
7. «Статистика и эффективность» запрашивается только при открытии блока или смене периода. Используется готовый read-only агрегат OpenCode по всем проектам; плагин не создаёт историю или новую базу и не хранит тексты диалогов. Взаимоисключающие категории: U = обычный вход, R = чтение кэша, W = запись кэша; полный вход = U+R+W, полный выход = output+reasoning. KPI: доля чтения = R/(U+R+W), амортизация записи = R/W; UI показывает числитель и знаменатель. Отсутствующие данные и нулевой знаменатель — `—`, а не ноль. База дня — предыдущие календарные сутки до того же времени, база недели — предшествующие 7×24 ч; текущий и базовый запросы независимы. Сравнения моделей — только внутри одного provider+model. Вход, чтение кэша и переиспользование получают независимые статусы; общий статус — худший из доступных. Зелёный/жёлтый/красный показывают отклонение от сопоставимой базы, серый — отсутствие базы или недостаточность данных без выдуманных числовых дельт. Цвет не означает качество ответа, денежную экономию или экономию квоты; объём выхода оценивается только как объём.
8. Диагностика лишь читает события/сессии OpenCode и записывает собственный ограниченный JSONL в `~/.local/share/opencode/quota-guard/diagnostics.jsonl` (или под `XDG_DATA_HOME`). Хранение до 7 дней и 10 МБ; только технические ID, время, модель, токены, паузы, квоты и маркеры событий. Не сохраняются тексты, названия сеансов, пути, содержимое файлов, аргументы инструментов, native/error/metadata payload и credentials. Запись best-effort: ошибка хранения не влияет на квоты, скорость, предупреждения или управление.

## Как считается скорость LLM

- **Вход, ток/с** = (`input` + `cache.read` + `cache.write`) / время от создания шага до первого токена.
- **Выход, ток/с** = (`output` + `reasoning`) / время от первого токена до конца потока.

Это фактические счётчики OpenCode и **средняя скорость завершённого шага**, а не мгновенная скорость между отдельными токенами. Секция «Скорость LLM» закреплена в каждой карточке квоты: при активности показывает все активные шаги этого провайдера, в простое — один последний замер с пометкой «последний шаг», при отсутствии истории — «Нет измерений». Отдельный блок для прочих провайдеров содержит только активные модели. Во время работы предыдущие точные метрики помечены «пред.». Накопленные токены всей сессии обновляются событием `session.usage.updated`. «Вход шага» — полный вход одного обращения (`input + cache.read + cache.write`), а не текущий размер контекста; рядом показаны обычный вход, чтение и запись кэша. Большие числа сокращаются (`k`, `M`, `B`), точные значения доступны в tooltip. Тексты сообщений не передаются.

## Установка

Плагин локальный. В глобальном конфиге OpenCode (`~/.config/opencode/opencode.json`) добавьте явную запись с `file:///`-URL к каталогу плагина:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    "file:///home/user/.config/opencode/plugins/quota-guard"
  ]
}
```

Windows: тот же `file:///`-URL с прямыми слеши и вашим домашним каталогом (без пробелов в пути).

Затем:

```sh
cd <plugin-dir>
npm install
npm run build     # собирает dist/gui-experimental.cjs (Desktop GUI)
```

Конфиг применяется без перезапуска: OpenCode следит за файлами и перезагружает плагины. Для принудительной перезагрузки — `/reload`. Пересборка GUI (`npm run build`) также запускает горячую перезагрузку GUI-бандла в Desktop.

Проверка загрузки: `opencode plugin list` → `quota-guard local`; в Desktop — Settings → Extensions → Plugins → `quota-guard` активен.

## Использование

### Desktop

1. Плитка в заголовке окна: **«Квоты: NN%»** (худшее окно) или **«Квоты: выкл»** — открывает панель.
2. Боковая область сессии: **«+» → «Квоты LLM»**; панель открывается вкладкой «Квоты LLM».
3. Кнопка **«Обновить»** — принудительный запрос квот (`refresh: true`).
4. Чекбокс **«Мониторинг и предупреждения»** — общий выключатель.
5. Секция **«Управление»**: чекбоксы «Опрос: <провайдер>»; select «Модель текущей сессии» + кнопка **«Переключить модель сессии»** (активна только когда выбрана другая модель).
6. **Settings → «Квоты LLM»**: Switch мониторинга, Switch по провайдерам, числовые пороги (warning/critical), интервал опроса (1/5/15/60 мин), кнопка «Сохранить».
7. Команда composer: `/quota-status` — текстовый статус всех провайдеров.
8. **«Диагностика»** загружается по требованию: «Сегодня»/«7 дней», вкладки «Холодные», «Проекты», «Время». Холодный шаг — эвристика: полный вход ≥100k и чтение кэша ≤20%; отдельно отмечается нулевое чтение. Пауза сравнивается только с предыдущим шагом того же сеанса. История квот начинается после установки этой версии; повторные неизменные замеры сворачиваются, изменения указаны в процентных пунктах. Совпадения с компакцией, моделью или загрузкой плагина не означают доказанную причину.

### TUI

- `/quota-status` — статус и режим.
- Сайдбар Usage даёт сторонний `opencode-usage-monitor` (если установлен): `Ctrl+X` затем `B`, `/usage-refresh`. Quota Guard его не заменяет и не модифицирует.

### RPC (HTTP)

Контракт: `POST /api/rpc/quota-guard/<method>?location[directory]=<project>` с телом `{"input": …}`; ответ `{"output": …}`. Ошибки — типизированные (`rpc.<id>.<error>`).

| Метод | Input | Output / ошибки |
| --- | --- | --- |
| `status` | `{refresh?: boolean}` | снимок: `enabled`, `mode`, `thresholds`, `monitoring`, `refreshMs`, `providers[]` (у ChatGPT — `credits`), `lastRefreshAt`, `stale`, `automaticActions` |
| `configure` | `{enabled?, monitoring?: {id: boolean}, warningPercent?, criticalPercent?, refreshMs?}` | новый снимок; невалидные числа игнорируются (текущие значения сохраняются) |
| `models` | `{sessionID}` | `{current?, options[]}`; ошибка `session_not_found` |
| `stats` | `{period?: "day" | "week"}` | текущий агрегат, `efficiency` (U/R/W, readShare, amortization, output/reasoning), `baseline` с независимой доступностью, `deltas`, `modelComparisons[]`; неизвестные значения — `null` |
| `diagnostics` | `{period?: "day" | "week"}` | существующая локальная история без refresh: `coldSteps[]`, `projects[] → roots[] → models[]/subagents[]`, `timeline[]`, `coldRule`, `retentionDays=7` |
| `switchModel` | `{sessionID, providerID, modelID}` | `{switched: true, providerID, modelID}`; ошибки `session_not_found`, `switch_failed` |

Событие `updated` (`{status}`) рассылается после каждого обновления снимка; GUI подписан на него.

Пример:

```sh
opencode api post '/api/rpc/quota-guard/status?location%5Bdirectory%5D=%2Fpath%2Fto%2Fproject' \
  --data '{"input":{"refresh":true}}'
```

## Диагностика

| Симптом | Действие |
| --- | --- |
| Нет панели/плитки в Desktop | проверить явную `file:///`-запись в конфиге; Settings → Extensions → Plugins → Reload; `npm run build` |
| ChatGPT: «OAuth account ID missing» | повторный вход через `/connect` → OpenAI → **Codex browser (legacy)**; token-sharing вход не даёт accountID |
| Kimi: нет плана | план берётся из `GET /me`; при 404/403 карточка покажет окна без плана |
| ChatGPT: нет строки кредитов | API вернул `credits` без баланса либо подписка без кредитов — строка скрыта |
| Кнопка переключения модели неактивна | выбрана текущая модель сессии — выберите другую |
| `models` без `current` | новая сессия ещё не имеет модели — это нормально |
| «Диагностика» пуста | история начинается после установки 0.12.0; выполните новые шаги или дождитесь настоящего обновления квоты |
| «Диагностика сейчас недоступна» | локальный журнал недоступен; квоты и предупреждения продолжают работать, проверьте права каталога данных OpenCode |

## Конфиденциальность

Репозиторий не содержит учётных данных, персональных путей и инфраструктурных имён: только код, тесты, документация и MIT-лицензия. Секреты живут в OpenCode auth-store, переменных окружения и plugin-storage пользователя.
